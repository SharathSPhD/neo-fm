# UI localization

Languages: English (source), हिन्दी, தமிழ், తెలుగు, ಕನ್ನಡ, বাংলা.

- Strings live in `apps/web/lib/i18n/locales/<lang>.ts`; `en.ts` defines the keys.
- Language is chosen server-side: cookie `neo-fm-lang` first, then `Accept-Language`, then English. The switcher in the nav and user menu writes the cookie and refreshes.
- Server components use `serverI18n()`; client components use `useUiLang()`; JSX text can use `<T k="..." />`.
- `{name}` placeholders and the `[[accent]]` marker must match English in every locale.
- `tests/lib/i18n-coverage.test.ts` fails CI when a locale misses a key, a key used in code is undefined, a key is unused, or placeholders drift.

## Review status

All non-English locales are first-pass translations marked `pending-review` in `TRANSLATION_STATUS` (`lib/i18n/ui-strings.ts`); the switcher flags them. After a native speaker signs off, flip that locale to `reviewed`.

Terms and Privacy show a localized plain-language summary above the governing English text.

## Intentionally left in English

- Edge-rendered images (Open Graph, share card, dedication image) and `/admin/health`.
- Style-preset titles/descriptions and raga, tala and instrument names (data from `@neo-fm/style-presets` and the song document).
- Raw server or API error text, and user-generated content.
- Email templates (rendered outside the web app).

## Native review of UI strings

Reviewers use a private link instead of a GitHub flow. Needs migration `0076_ui_review.sql` applied.

1. Mint a link per language (operator, Bearer `ADMIN_SECRET`; the token is shown once, expires in 14 days by default):
   `curl -X POST -H "Authorization: Bearer $SECRET" "$APP/api/admin/ui-review?action=token&lang=kn&alias=Kannada%20reviewer%20A"` → `path: /ui-review/<token>`.
2. The reviewer opens the link. Every string is listed with its screen, the English source and the current translation. They press **Looks good** or edit the text and **Save my edit** (`{placeholders}` and `[[markers]]` must survive). "See this screen in kn" opens the public page in that language.
3. Progress: `GET /api/admin/ui-review?action=report`.
4. Export the patch: `GET /api/admin/ui-review?action=patch&lang=kn > kn.patch.json` (`&format=md` gives a table for the PR description). Verdicts made against an older translation are ignored; competing edits list the latest as the change and the rest as alternatives.
5. Apply and open a PR: `node apps/web/scripts/apply-ui-review.mjs kn.patch.json --mark-reviewed` rewrites `lib/i18n/locales/kn.ts` line by line (review `git diff`) and flips `TRANSLATION_STATUS.kn` to `reviewed` only if every key has a verdict.
6. Revoke a link early: `POST ?action=revoke&alias=...`.

No personal data is stored: a reviewer is a hashed token plus an optional alias. Pages send `no-referrer` and `no-store`.
